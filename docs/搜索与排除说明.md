# 搜索与排除：完整规则和核验例子（2026-10-26）

## 一、你发现的高亮问题：是 UI 错误，搜索逻辑本身没有问题

搜「用户 A」时，结果只来自作者名和 @用户名：核心的 SQL 在只选「用户」时根本不会去比对标签和正文（`core/src/store.rs` 的 `feed_filtered`，`core/src/library.rs` 的 `feed` 在只有作者字段时不展开标签）。错的是卡片高亮：以前高亮只看「搜了哪些词」，不看「在哪里搜」，所以正文和标签里出现的 A 也被涂黄。

现在高亮只出现在实际被搜索的位置（`SearchMarks`，iOS 与 Mac 共用）：

| 搜索 | 高亮位置 |
|---|---|
| `用户 al` | 只在作者名、@用户名 |
| `贴文 猫` | 只在正文 |
| `标签 猫` / `我的 猫` / `AI 猫` | 只在标签 |
| `猫`（不加字段） | 作者、正文、标签都高亮 |
| `猫 -用户` | 正文和标签高亮，作者不高亮 |

这一点已在 Mac 合成资料库上核对：`用户 al` 只命中 Alice（@alice_art）的帖子，卡片上只有「Al」「al」被高亮，正文里的同字没有。

## 二、搜索的完整规则（加入排除后）

搜索框里的每个词按空格变成一个胶囊。胶囊分三类：

1. **字段**：标签、贴文、用户——决定词在哪里找。
2. **条件**：我的 / AI / 共同 / 全部（标签来源）、视频 / 照片（媒体类型）、文件夹 X、最近、外部导入。
3. **搜索词**：其他任何词。

规则：

- **每个搜索词都必须命中**（与），命中位置是「当前字段」中的任意一处（或）。
- **不加字段时**在标签、正文、作者三处都找；只加了「我的 / AI / 共同」这类来源条件时只在标签里找（来源只对标签有意义）。
- **语义模糊搜索**开启时，正词还会通过意思相近的标签扩展（例如「墙」也能找到「白墙」的媒体，标签相近的词也会在正文里找）；排除词**不**做语义扩展，只按「包含」判断，避免意外排除太多。
- **文件夹 / 最近 / 外部导入 / 视频 / 照片**只缩小范围，不改变在哪里找。
- 与主页的筛选胶囊（仅 #标签、只看某作者、未认可、已损坏……）同时生效。

### 排除（前面加减号）

减号可以是 `-`、全角 `－`、`−`、`–`（中文输入法打出的也算）。单独一个 `-` 不算排除，是普通字符。

| 写法 | 含义 |
|---|---|
| `-词` | 排除在「当前字段」里**包含**这个词的媒体（标签包含该词、正文包含、作者名或 @用户名 包含，按字段决定） |
| `-用户` / `-贴文` / `-标签` | 这次搜索不在该字段里进行（正词和排除词都不再看这个字段） |
| `-我的` | 不算我加的或认可的标签（只看 AI 单独加的标签） |
| `-AI` | 不算 AI 加的标签（只看我单独加的标签） |
| `-共同` | 不算我和 AI 都加了的标签 |
| `-视频` / `-照片` | 不要这一类媒体 |
| `-文件夹 名称` | 排除这个文件夹里的媒体（可以排除多个） |
| `-最近` | 不要「最近添加」的帖子 |
| `-外部导入` | 不要散装媒体 |
| `-全部` | 没有意义，作为普通搜索词处理 |

自相矛盾的搜索直接显示「没有匹配的媒体」：`视频 -视频`、`最近 -最近`、`文件夹 旅行 -文件夹 旅行`、有搜索词却把三个字段都排除（`猫 -标签 -贴文 -用户`）。

界面：排除胶囊在 iOS 上带红色 ⊖ 图标，在 Mac 上是红色「−词」胶囊；VoiceOver 读作「排除：词」。输入 `-` 时，建议列表变成「排除」一组：可以排除的条件、「排除含有某词的媒体」、匹配的标签和文件夹。

搜索关键词按界面语言识别：中文界面用「用户」「贴文」等，英文界面用 User / Text / Tags…，日文界面用ユーザー／本文／タグ…（避免中文用户搜英文正文里的 photo 之类时被误认成条件）。

## 三、可以核验的例子

以下例子已写成核心测试（`core/tests/search_rules.rs` 的 `report_examples`），全部通过。资料库：

| 媒体 | 帖子作者 | 正文 | 标签（来源） |
|---|---|---|---|
| m0 | Alice @al | 今天的猫和白墙 | 猫（我） |
| m1 | 小白 @xiaobai | a Dog runs | 白墙（AI） |
| m2 | Bob @bobcat | CAT 与 狗 | cat（我和 AI） |
| m3 | Alice @al | （无） | 墙纸（AI） |

| 搜索 | 结果 | 说明 |
|---|---|---|
| `用户 al` | m0、m3 | 只看作者 |
| `猫` | m0 | 标签、正文、作者都找；cat 不等于 猫 |
| `cat` | m2 | 标签 cat、正文 CAT（不分大小写）、作者 @bobcat 都在 m2 |
| `墙 -猫` | m1、m3 | m0 正文有「白墙」但也含「猫」，被排除 |
| `-al`（只有排除） | m1、m2 | 作者名或 @ 含 al 的 m0、m3 被排除 |
| `墙 -用户` | m0、m1、m3 | 只在标签和正文里找 |
| `al -用户` | 无 | al 只出现在作者里，而作者被排除了 |
| `墙 -AI` | m0 | AI 加的「白墙」「墙纸」不算；m0 靠正文命中 |
| `标签 墙 -我的` | m1、m3 | 只看 AI 单独加的标签 |

另有属性测试 `sql_search_agrees_with_rule`：400 个随机资料库（随机正文、作者、标签及来源、正词、排除词、字段、来源和来源排除），数据库查询结果与纯规则 `rules::search_matches` 逐个一致；`excluded_folders_recent_and_loose` 检查文件夹 / 最近 / 散装的排除。

在 App 里核验（Mac 或 iPhone）：

1. 搜 `用户 某个作者的一部分` —— 只有作者被高亮，正文里同样的字不再高亮。
2. 搜 `-` —— 列表出现「排除」一组。
3. 搜 `某个标签 -另一个标签` —— 带有后者的媒体消失；在 iOS 上胶囊带红色 ⊖。
4. 搜 `视频 -视频` —— 显示「没有匹配的媒体」。
5. 搜 `-文件夹 ` 然后选一个文件夹 —— 那个文件夹里的媒体都不出现。
6. 搜 `猫 -贴文` —— 正文里有猫但标签和作者没有的媒体消失。

## 四、目前的边界

- 排除词只按「包含」判断（例如 `-猫` 也会排除标签「小猫」和含「猫」的正文），不按意思相近排除。
- 大小写：英文按 SQLite 的规则只忽略 ASCII 大小写，带重音的大写字母（如 É）与小写不视为相同，这与以前的正词行为一致。
- 条件词只认当前界面语言（及其别名）；要搜一个正好是条件词的词，可以在建议列表里点「搜索「…」」。
